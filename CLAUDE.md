# horde — Project Conventions

## What this is

Cloud launcher for orc workflows. See SPEC.md for design, ORC_CONTRACT_EXPECTATIONS.md for the orc interface boundary.

## Language & Dependencies

- Go 1.24+, module: `github.com/jorge-barreto/horde`
- CLI: `github.com/urfave/cli/v3`
- SQLite: `modernc.org/sqlite` (pure-Go driver; local run history)
- YAML: `gopkg.in/yaml.v3` (project config)
- AWS (v0.2): `github.com/aws/aws-sdk-go-v2` (DynamoDB, SSM, STS, CloudWatch Logs, S3, ECS)

## Commands

```bash
make build                    # build cmd/horde
make unit-test                # fast Go tests; no Docker, no AWS. What CI runs on every PR.
make integration-test         # real Docker, real horde, real orc (~2 min). CI runs this too.
make vet                      # go vet

# ECS end-to-end tests — real AWS stack, developer-local only (never CI).
# Needs `.env` with AWS_PROFILE + HORDE_E2E_*=1 and a live SSO token.
make e2e-up                   # deploy CDK stack (~5 min cold / ~2 min warm)
make e2e-test                 # run full TestECS_* suite against it (~15 min)
make e2e-down                 # destroy stack (~3 min). ALWAYS run when done.

# Free AWS-backed check (no resources created, no charges).
make bootstrap-validate-test  # ValidateTemplate on rendered CloudFormation
```

## CI

`.github/workflows/ci.yml` runs on every PR to main and every push to main.
Three required jobs: `unit-test`, `integration-test`, `cdk-test`. If any
fails, the PR can't merge. Reproduce locally with the matching `make`
target (or `cd cdk && npm ci && npm run build && npm test` for cdk-test).

## Git

- Commit messages: short and direct. No "Co-Authored-By", "Generated by", or any AI attribution lines.
- Stage specific files — never `git add .` or `git add -A`.

## Code Style

- Standard Go conventions. `gofmt` and `go vet` clean.
- Errors are returned, not panicked. Wrap with context: `fmt.Errorf("loading config: %w", err)`.
- Major interfaces in their own files (`store.go`, `provider.go`). Implementations in separate files (`sqlite.go`, `dynamo.go`, `docker.go`, `dockerimage.go`).
- Tests next to implementation: `foo.go` → `foo_test.go`.
- Never combine `t.Parallel()` with `t.Setenv`, `t.Chdir`, or `os.Setenv` — `testing.T.Setenv` panics on tests with parallel ancestors. If a test needs env mutation, it cannot be parallel.

## Architecture

- `cmd/horde/` — CLI entry point, all commands (launch, retry, status, logs, kill, results, hydrate, list, clean, shell, bootstrap, push, update, version, docs), factory for provider/store
- `internal/bootstrap/` — CloudFormation template generation + project-slug derivation for `horde bootstrap` (v0.2)
- `internal/provider/` — Provider interface (`provider.go`) + Docker implementation (`docker.go`, `dockerimage.go`); ECS provider in v0.2
- `internal/store/` — Store interface (`store.go`) + SQLite (`sqlite.go`) and DynamoDB (`dynamo.go`, v0.2) implementations. Both pass shared conformance tests.
- `internal/config/` — Git remote URL resolution, `.env` file validation, `.horde/config.yaml` project config, SSM parameter loading (v0.2)
- `internal/awscfg/` — AWS SDK config loading, credential diagnostics
- `internal/docs/` — Built-in documentation system (`horde docs <topic>`)
- `internal/runid/` — Run ID generation (12-char alphanumeric via crypto/rand)
- `docker/` — Worker Dockerfile, entrypoint.sh, git-askpass.sh (embedded into binary via `workerfiles.go`)
- `cdk/` — `@horde.io/cdk` npm package: TypeScript CDK construct (`HordeWorker`) + status-sync Lambda. Alternative to `horde bootstrap` for teams with an existing CDK app. Emits the same SSM JSON shape consumed by `internal/config/ssm.go`. (v0.2)
- `worker/` — Optional project-specific Dockerfile extending base image
- `test/integration/` — End-to-end tests against real Docker containers

## Key Design Decisions

- Git is a hard requirement — repo URL inferred from local git remote
- Optional project config in `.horde/config.yaml` (volume mounts; `secrets:` block declares extra env-var secrets beyond the two canonical `CLAUDE_CODE_OAUTH_TOKEN`/`GIT_TOKEN` — see `horde docs config`); secrets from `.env` file (gitignored) via `docker run --env-file`
- GIT_TOKEN protected via `GIT_ASKPASS` credential helper — never in process args or `.git/config`
- SQLite for local run history (`~/.horde/horde.db`); DynamoDB for shared team history (v0.2)
- Store selection follows provider: docker → SQLite, aws-ecs → DynamoDB
- Run timeout (default 24h) enforced lazily — checked on status/list/results calls, not a background timer
- Provider.Launch returns `*LaunchResult` with `InstanceID` + `Metadata map[string]string` (no provider-specific fields on the generic type)
- User labels (`horde launch --label k=v`) live in `Run.Labels`, a dedicated column/attribute strictly separate from provider-internal `Run.Metadata` (cluster_arn, log_group, …) — set once at launch, never on `RunUpdate`, carried across `retry`. `horde list` filters via `store.ListRuns(RunFilter)` (status set, workflow, ticket, labels AND-exact, started_at range): DynamoDB filters server-side via FilterExpression on the by-repo GSI; SQLite fetches repo rows and applies the shared `matchesFilter` predicate. Status is filtered *after* `Finalize()` since finalize can flip a run terminal mid-call.
- Two-layer Docker image: base (`horde-worker-base:latest`) with orc/claude/tools, project image (`horde-worker:latest`) optionally extends via `worker/Dockerfile`
- Containers preserved after stop/kill for retry and shell access; workspaces persist at `~/.horde/workspaces/<run-id>/`
- Recoverable runs: orc exit 2 → `timed_out`, exit 4 → `rate_limited` (in `mapExitCode`); both are terminal-but-recoverable, distinct from `failed`/`killed`. `horde retry` accepts all four. Status is free-text (no schema migration); `IsTerminal()` and store filters handle them — active filters are `{pending,running}` allowlists. See `horde docs retry`.
- ECS recoverable runs reproduce the Docker on-host-workspace guarantee via S3: Fargate has no persistent FS, so the worker syncs `~/.claude` (agent session) + full `/workspace` (committed + uncommitted + `.git`) to S3 on SIGTERM and restores both on `horde retry` with the same run ID. orc runs backgrounded so SIGTERM reaches it and its interrupt-save finishes before the uploads; orc's true exit code is preserved across the signal. Uses the task role's S3 access — no git push / repo write.
- Status Lambda records ECS `stop_code`/`stop_reason` into the run's `metadata` map (before the terminal-status guard, so a synchronous `horde kill` still records it). A spot interruption surfaces as `stop_code == "TerminationNotice"`. The CDK (TS) and bootstrap (Python) lambdas are kept in lockstep.
- Status detection is lazy: `prov.Finalize()` runs on status/list/results to detect completed/timed-out containers and collect artifacts (a no-op for every terminal status, so terminal ECS runs read from the store and never re-hit live ECS)
- `--json` is a stable machine contract (`cmd/horde/jsonv1.go`, `horde docs json`): under `--json` stdout carries exactly one JSON object, real errors emit an `ErrorV1` envelope on stdout via the root `ExitErrHandler` (human `error:` line stays on stderr), and exit codes are binary (0 for launched/duplicate/capped, 1 for real errors). Do NOT mark a flag `Required: true` on a `--json`-aware command — urfave validates it before the Action and prints help to stdout, bypassing the envelope; validate inside the Action instead.
- Sidecar containers (`HordeWorkerProps.sidecars`, CDK-only — `horde docs cdk`): extra containers added to the worker Fargate task, sharing its network namespace (localhost-reachable) and lifecycle. Construct defaults `essential:false` + logging to the worker log group; reserved name `horde-worker`. Run status is derived from the **worker** container's exit code found BY NAME, never `containers[0]` — because the ECS event's container order isn't guaranteed once sidecars exist. This by-name selection is duplicated in THREE readers that must stay in sync: the TS Lambda (`cdk/src/status-lambda/index.ts`), the Python Lambda (`internal/bootstrap/templates/stack.yaml.tmpl`), and the Go lazy-reconciliation path (`internal/provider/ecs.go::Status`). The worker name `horde-worker` is a cross-language contract (also `internal/provider/ecs.go` const + `cdk` `WORKER_CONTAINER_NAME`); changing it means changing all of them.
