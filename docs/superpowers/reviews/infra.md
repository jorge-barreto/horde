## WARNING
- [internal/bootstrap/templates/stack.yaml.tmpl:708-712 vs cdk/src/status-lambda/index.ts:148] `num()` coercion is NOT identical between the two lambdas — a lockstep asymmetry. Python `num(v)` does `int(v)` in a try/except, so it accepts numeric strings (`int("54791")` → 54791) and truncates floats (`int(1.9)` → 1) and coerces `bool` (`int(True)` → 1). TS `num(v)` is `typeof v === "number" && Number.isFinite(v) ? v : 0`, so it returns 0 for a numeric string, passes floats through unchanged (1.9 → 1.9), and returns 0 for bool. For the contracted input shape (integer token counts, per ORC_CONTRACT_EXPECTATIONS.md costs.json) both produce identical results, so this does not affect correct runs. But on any malformed/edge costs.json the two backends would silently write *different* token values for the same run — exactly the drift the lockstep contract exists to prevent. Suggested fix: make TS `num` coerce strings too (e.g. `const n = typeof v === "number" ? v : Number(v); return Number.isFinite(n) ? n : 0`) OR make Python reject non-int with `int(v) if isinstance(v, int) else 0`, so both agree on the same rule. (Note the authoritative Go reader, `costsFile` in internal/provider/docker.go, uses strict `int` JSON fields and returns nil for the whole file on a float/string — a third distinct behavior; none of the three match exactly on bad input.)
- [internal/bootstrap/template_test.go:521-591] The Python lambda's new token logic has no test coverage. `TestRender_StatusLambdaPython` asserts render + YAML-parse + a substring allowlist that was NOT extended for tokens (`costs.json`, `fetch_token_usage`, `input_tokens`, the 5 attribute names, the `if tokens is not None:` block are all unchecked), and `bootstrap-validate-test` runs CloudFormation ValidateTemplate which never executes/syntax-checks the embedded Python. The TS side has two new tests (present + absent costs.json) but the Python twin — the half a bootstrap-tier user actually runs — could silently break (wrong attribute name, bad indentation, `num` regression) and pass all CI. Suggested fix: extend the substring allowlist to include the 5 store attribute names and `costs.json`/`fetch_token_usage`, and/or add a test that extracts the ZipFile and `py_compile`s it (an interpreter-presence-guarded compile would also have caught any syntax regression).
